# Cosmo OS development guidance

Continue this existing project directly in Codex. Preserve unrelated working-tree changes and existing features.

For joint Supplier Portal work, read the shared status at [Supplier Portal project status](../Supplier%20Portal/docs/project-status.md) and the applicable project skills under C:/dev/Supplier Portal/.cursor/skills/. Update that concise status after meaningful implementation or validation instead of maintaining competing progress reports.

Read applicable rules under .cursor/rules/ and any task-specific instructions. Before Next.js changes, consult the installed documentation where available. Preserve current authorization and company scoping.

ERP1/ERP2 data flows through Cosmo OS to Supplier Portal. Preserve versioned OSF, product-media and purchasing-history contracts and separate credentials by purpose. Company staff own purchasing complexity and physical receipt verification.

Work autonomously within approved local development and test scope. Obtain task-specific approval before hosted writes, migrations, production access, credential changes, or live external integrations. Earlier test approval does not authorize rollout.

Recovery setup is postponed except preparation for the one-time Supplier Portal development backup. Key generation, Neon connections, backups and restores require specific approval. Do not place secrets in documentation or logs.
